## 1. Executive Summary & Step 0 Synthesis

### 1.1 Vectorized API Signature & Contract
All heuristics generated by LLMs, whether in evolution, evaluation, or RL rollouts, strictly adhere to the single canonical vectorized priority API:

```python
def priority(adj, colors, sat, deg, uncolored_deg) -> np.ndarray:
    """
    adj:           (n, n) bool ndarray, symmetric, no self-loops (read-only)
    colors:        (n,) int64 ndarray, -1 = uncolored, >=0 color id (read-only)
    sat:           (n,) int64 ndarray, number of distinct colors among colored neighbors (read-only)
    deg:           (n,) int64 ndarray, total degree in full graph (read-only)
    uncolored_deg: (n,) int64 ndarray, number of uncolored neighbors (read-only)
    
    Returns:
      (n,) float ndarray of vertex priority scores. Higher score = color earlier.
    """
```

- **Purity Rules:** Pure deterministic function. No globals, no internal state across calls, no I/O, no randomness (`np.random` is forbidden). All inputs are marked read-only views (`flags.writeable = False`). Any attempt to mutate inputs or return non-finite/ill-shaped arrays triggers an immediate sandbox rejection.
- **Framework Tie-Breaking:** In `evaluator/coloring.py:greedy_color`, the uncolored vertex with `max(scores)` is colored next; ties are broken deterministically by **lowest vertex index** (`candidates[0]`).
- **Baseline Implementations:**
  - DSATUR: `sat * (n + 1) + uncolored_deg` (verified identical to standalone fast Numba `dsatur(adj)`).
  - RLF: Vectorized exact priority `rlf_priority` tracking active color class $k = \max(colors)$, candidates $cand$, excluded $excl$, and candidate score $n_e \cdot (n + 1) - n_c$ (verified identical to standalone Numba `rlf(adj)`).

### 1.2 4-Layer Sandbox Invocation & Verification
The sandbox in `gate/evolved/sandbox.py` executes candidates through 4 defensive layers:
1. **AST Filter (`validate_ast`):** Static verification that the AST defines `priority` with exactly 5 positional parameters, forbids all default arguments, forbids identifiers starting with `_`, bans `import`/`eval`/`exec`/file I/O, and enforces an explicit whitelist of allowed NumPy operations and array methods.
2. **Namespace Isolation:** Whitelisted `__builtins__` only, with a secure C-extension import shim `_safe_import` that allows internal `numpy.*` helper modules while blocking all external modules (`os`, `sys`, `subprocess`).
3. **Statelessness & Purity Check (`check_statelessness_and_purity`):** Executed on partial coloring states before running full graphs; detects mutations to read-only arrays and checks deterministic repeatability.
4. **Subprocess Hard-Timeout & Resource Isolation (`evaluate_candidate_safe`):** Runs in a separate worker process spawned with `mp.get_context("spawn")`, scrubbed of all `*_API_KEY` environment variables, threadpool pinned to 1 thread (`OMP_NUM_THREADS=1`), monitored with `psutil` with a hard 1.5 GB RSS memory limit, and terminated via `proc.kill()` if timeouts or memory caps are breached.
5. **Independent Coloring Verifier (`evaluator/verify.py`):** Independent code path verifying proper coloring (no adjacent vertices share the same color, all vertices colored $\ge 0$). Color counts are only recorded if `verify(adj, colors) == True`.

### 1.3 Reference Baselines $R(F)$ and `base_alg(card)`
- Per Decision D-2, the primary benchmark is:
  $$R(F) = \min(\text{mean DSATUR}(S), \text{mean RLF}(S))$$
  computed on the exact same graph set $S$ of the split.
- Per Decision D-3, `base_alg(card)` is determined once on `teacher_val` (seeds 3000-3019) as:
  $$\text{base\_alg}(card) = \text{argmin}_{A \in \{\text{DSATUR}, \text{RLF}\}} \left(\text{mean\_colors}_A(\text{teacher\_val})\right)$$
  For any graph $g$, $c_{base}(g)$ is the color count of `base_alg(card)` evaluated on $g$.

## 2. Design of `eval/coverage.py`

### 2.1 Canonical Definition of "Beats R(F)"
A candidate heuristic $h$ evaluated on graph set $S(F) = \{g_1, \dots, g_M\}$ for card $F$ produces color counts $c_h(g_m)$ for each graph.

**Definition:**
A candidate $h$ **beats $R(F)$** on card $F$ if and only if:
1. $h$ is **fully valid** on all graphs $g \in S(F)$ (passes AST, statelessness, verification, zero exceptions, zero timeouts).
2. The mean color count $\bar{c}_h = \frac{1}{|S(F)|} \sum_{g \in S(F)} c_h(g)$ satisfies:
   $$\bar{c}_h \le R(F) - \epsilon$$
   or equivalently:
   $$R(F) - \bar{c}_h \ge \epsilon$$
   where $\epsilon = 0.05$ by default (configurable).

**Key Rules:**
- **Strict Win Condition:** Ties do **NOT** count as wins. If $|\bar{c}_h - R(F)| < \epsilon$ or $\bar{c}_h \ge R(F)$, it is NOT a win.
- **Reference Calculation:**
  $$R(F) = \min\left(\frac{1}{|S|} \sum_{g \in S} c_{\text{DSATUR}}(g), \; \frac{1}{|S|} \sum_{g \in S} c_{\text{RLF}}(g)\right)$$
  Both DSATUR and RLF are measured on the identical graph split $S(F)$.

### 2.2 Unbiased `pass_at_k` Estimator (Chen et al. 2021)
When $n$ samples are generated per problem, of which $c$ samples are winners ($c \le n$), the probability that at least one of $k$ randomly chosen samples is a winner without replacement is estimated as:
$$\text{pass@}k = 1 - \frac{\binom{n - c}{k}}{\binom{n}{k}}$$

#### Numerically Stable Formulation
Direct computation of combinations $\binom{n}{k}$ easily overflows for large $n$. We formulate this via log-gamma / log-factorial:

$$\ln \frac{\binom{n - c}{k}}{\binom{n}{k}} = \ln \Gamma(n - c + 1) - \ln \Gamma(n - c - k + 1) - \ln \Gamma(n + 1) + \ln \Gamma(n - k + 1)$$

Alternatively, using the telescoping product:
$$\frac{\binom{n - c}{k}}{\binom{n}{k}} = \prod_{j=0}^{k-1} \left(1 - \frac{c}{n - j}\right)$$

#### Invariant Properties & Edge Cases:
1. **$k > n$**: Undefined. Raise `ValueError(f"k ({k}) cannot exceed n ({n})")`.
2. **$c = 0$** (zero winners): $\text{pass@}k = 0.0$.
3. **$n - c < k$** (number of non-winning candidates is strictly less than $k$): At least one winning candidate must be drawn in any subset of size $k$. Thus $\frac{\binom{n-c}{k}}{\binom{n}{k}} = 0$, so $\text{pass@}k = 1.0$.
4. **$k = 1$**: $\text{pass@}1 = 1 - \frac{n - c}{n} = \frac{c}{n}$ (unbiased sample success rate).
5. **$k = n$**: If $c \ge 1 \implies 1.0$; if $c = 0 \implies 0.0$.
6. **Numerical Clamping:** Due to floating-point rounding, always clamp the result to $[0.0, 1.0]$.

### 2.3 `coverage_at_k`
Given a set of $C$ cards:
- **Empirical `coverage_at_k` (when exactly $k$ candidates per card are evaluated):**
  For card $i$, let $W_i = 1$ if at least one candidate among the $k$ evaluated candidates beats $R(F_i)$ by $\ge \epsilon$, else $0$.
  $$\text{coverage@}k = \frac{1}{C} \sum_{i=1}^C W_i$$
- **Analytic `coverage_at_k` (when $n \ge k$ candidates are evaluated):**
  For each card $i$ with $c_i$ winning candidates out of $n$, the expected indicator of having at least 1 winner in a random sample of size $k$ is $\text{pass@}k(n, c_i, k)$.
  $$\mathbb{E}[\text{coverage@}k] = \frac{1}{C} \sum_{i=1}^C \text{pass@}k(n, c_i, k)$$
- **Zero Cards Edge Case:** If $C = 0$, return $0.0$ (avoid `ZeroDivisionError`).

### 2.4 `best_of_k`
Given $k$ candidates for card $i$ with mean color counts $\{\bar{c}_{h_1}, \dots, \bar{c}_{h_k}\}$:
- Quality of candidate $h$: defined as mean colors $\bar{c}_h$ (lower is better), or savings vs $R(F)$: $R(F) - \bar{c}_h$ (higher is better).
- For a card, the best candidate among the first $k$ is:
  $$\bar{c}_{best, i} = \min_{j \in \{1,\dots,k\}, \; h_{i,j} \text{ valid}} \bar{c}_{h_{i,j}}$$
- **Handling All Candidates Failing on Card $i$:**
  If all $k$ candidates fail, $\bar{c}_{best, i}$ is marked as failed. In aggregate reports:
  - `best_of_k_colors`: mean over cards where at least one candidate succeeded, alongside a reported card completion rate.
  - `best_of_k_savings`: relative to $R(F)$, failed cards can either be assigned zero savings ($0.0$) or penalized with a sentinel failure saving (e.g. $-1.0$). We recommend reporting both `best_of_k_mean_colors` and `best_of_k_savings_rf` with explicit failure policy (`"zero_savings"` fallback).

### 2.5 API Specification for `eval/coverage.py`

```python
"""eval/coverage.py: Canonical coverage metrics and pass@k estimators."""

from typing import List, Sequence, Optional, Union
import math
import numpy as np


def beats_rf(
    candidate_mean_colors: Optional[float],
    rf_mean_colors: float,
    eps: float = 0.05,
) -> bool:
    """Canonical test of whether a candidate beats R(F).
    
    A candidate beats R(F) iff candidate_mean_colors is not None and:
        candidate_mean_colors <= rf_mean_colors - eps
    Ties do NOT count as wins.
    """
    if candidate_mean_colors is None or not math.isfinite(candidate_mean_colors):
        return False
    return (rf_mean_colors - candidate_mean_colors) >= eps


def pass_at_k(n: int, c: int, k: int) -> float:
    """Unbiased estimator of pass@k (Chen et al. 2021).
    
    Parameters:
      n: total number of generated samples (n >= 1)
      c: number of winning/correct samples (0 <= c <= n)
      k: budget of samples considered (1 <= k <= n)
    """
    if k > n:
        raise ValueError(f"k ({k}) cannot be greater than n ({n})")
    if k <= 0 or n <= 0:
        raise ValueError(f"k and n must be positive integers, got k={k}, n={n}")
    if c < 0 or c > n:
        raise ValueError(f"c must satisfy 0 <= c <= n, got c={c}, n={n}")
    
    if c == 0:
        return 0.0
    if n - c < k:
        return 1.0
    if k == 1:
        return float(c) / float(n)
        
    # Stable product calculation
    prod = 1.0
    for j in range(k):
        prod *= (1.0 - float(c) / float(n - j))
    return float(np.clip(1.0 - prod, 0.0, 1.0))


def coverage_at_k(
    card_win_counts: Sequence[int],
    n_samples: int,
    k: int,
) -> float:
    """Compute expected coverage@k across cards given win counts per card.
    
    card_win_counts: list of number of winning candidates per card (length C)
    n_samples: total candidates generated per card
    k: target evaluation budget k <= n_samples
    """
    if len(card_win_counts) == 0:
        return 0.0
    probs = [pass_at_k(n_samples, c, k) for c in card_win_counts]
    return float(np.mean(probs))


def empirical_coverage_at_k(
    card_candidate_wins: Sequence[Sequence[bool]],
) -> float:
    """Compute empirical coverage@k when exactly k candidate win flags are provided per card."""
    if len(card_candidate_wins) == 0:
        return 0.0
    has_winner = [1.0 if any(c_wins) else 0.0 for c_wins in card_candidate_wins]
    return float(np.mean(has_winner))


def best_of_k(
    card_candidate_colors: Sequence[Sequence[Optional[float]]],
    rf_colors: Sequence[float],
    k: int,
    failed_savings_fallback: float = 0.0,
) -> dict:
```

### 3.2 Backend Interface & Lazy Loading Stubs
All generation models sit behind a single unified abstract base class:

```python
class GenerationBackend(ABC):

    def generate(self, prompt: str, n: int, temperature: float, seed: int) -> List[str]:
        """Generate n code completions for the given prompt."""
```

#### 1. MockBackend (Deterministic Synthetic Generator)
Used for all unit and integration tests. Based on `(seed, sample_idx)`, emits predictable code archetypes:
- **Sample 0 (DSATUR-like):** Implements exact DSATUR priority formula. Passes AST, statelessness, verify. Scores equal DSATUR; gap vs $R(F) \ge 0$, coverage = 0.
- **Sample 1 (RLF-like):** Implements exact RLF priority formula. Passes AST, statelessness, verify. Scores equal RLF; gap vs $R(F) \ge 0$, coverage = 0.
- **Sample 2 (Broken/AST Fail):** Contains syntax error or forbidden syntax (e.g. `import os`). Tested to verify proper recording of AST rejection without crashing.
- **Sample 3 (Timeout/Slow):** Contains a massive redundant Python loop to deliberately trigger per-graph timeout.
- **Sample 4+ (Superior Heuristic / Controlled Mock):** When configured, emits a priority formula that strictly beats $R(F)$ on synthetic test graphs to verify coverage detection.

#### 2. HFBackend, VLLMBackend, APIBackend (Lazy Stubs)
- **`HFBackend`:** Imports `torch`, `transformers`, `peft` **strictly inside `__init__` / `generate`**. If torch or transformers is missing, raises `ImportError("transformers, torch, and peft are required to use HFBackend")`.
- **`VLLMBackend`:** Imports `vllm` strictly inside `__init__`. If missing, raises `ImportError("vllm is required to use VLLMBackend")`.
- **`APIBackend`:** Reads API key from the designated environment variable (e.g. `GEMINI_API_KEY`, `DEEPSEEK_API_KEY`). If the environment variable is unset, raises `ValueError(f"API key environment variable '{env_var}' is not set")`. No keys are ever written to config or disk.

### 3.4 Evaluation Execution & Windows-Safe Architecture
- **Windows-Safe Multiprocessing:**
  Since `gate/evolved/sandbox.py:evaluate_candidate_safe` spawns its own isolated worker process via `mp.get_context("spawn")`, we coordinate candidate evaluations in `eval_model.py` using `concurrent.futures.ThreadPoolExecutor(max_workers=workers)`.
  This guarantees that:
  1. Each candidate is executed in a dedicated, sandboxed subprocess with strict RSS memory cap (1.5 GB) and hard timeout.
  2. No nested multiprocessing deadlocks occur on Windows.
  3. Clean termination and garbage collection of child processes.
- **Reference Precomputation:**
  For each family in the split, load its graphs and compute $\bar{c}_{DSATUR}$ and $\bar{c}_{RLF}$.
  Record $R(F) = \min(\bar{c}_{DSATUR}, \bar{c}_{RLF})$ and DSATUR runtime $t_{DSATUR}$.
- **Candidate Evaluation:**
  Each candidate code string is evaluated on the family's graphs. If valid, color counts are verified with `evaluator/verify.py:verify`.
  Behavioral fingerprinting is performed on probe graphs (seeds 9000-9009) to record color vector hash and ordering.

### 3.5 Disk Caching Mechanism
- **Cache Location:** `runs/eval/_cache/{cache_key}.json`
- **Cache Key Formulation:**
  $$\text{cache\_key} = \text{sha256}\left(\text{code\_hash} + \text{"\_"} + \text{graph\_set\_id} + \text{"\_"} + \text{config\_version}\right)$$
  - `code_hash`: SHA256 of candidate Python code.
  - `graph_set_id`: String uniquely identifying the graph split, e.g. `{family_id}_{split}_{n_graphs}_{split_seed_hash}`.
  - `config_version`: Version string incorporating timeout thresholds and sandbox version.
- **Cached Content:**
  JSON storing: `status`, `color_counts`, `mean_colors`, `runtime_s`, `probe_fingerprint`, `error`.
- **Reporting:** Cache hits and misses are tracked; `cache_hit_rate = hits / (hits + misses)` is reported in summary.

### 3.6 Test-Lock Mechanism
- **Rule:** Any split whose name starts with `"test"` (`test`, `test_pilot`, `test_interp`, `test_extrap`, `test_comp`, `test_heldout_type`) must only be evaluated ONCE per `(model_name, split, config_hash)`.
- **Lock File:** `runs/eval/_locks/{split}_{sanitized_model}_{config_hash}.done`
- **Behavior:**
  1. If lock file exists and `--force-unlock` is FALSE:
     Raise `RuntimeError(f"Test split '{split}' has already been evaluated for this configuration. Repeated evaluation is blocked to prevent data snooping. Pass --force-unlock to override.")`.
  2. If `--force-unlock` is TRUE:
     Proceed, but record `"force_unlock_used": true` in `config.json` and `summary.json`, and print a prominent warning.
  3. Upon successful evaluation of a test split, create the `.done` lock file containing JSON metadata (timestamp, run_id, git commit, full config).
  4. Non-test splits (`val`, `probe`, `train`, `teacher_val`) are never locked.

## 4. Design of `train/reward.py` (GRPO Reward Engine)

### 4.1 Decoupled Architecture
`train/reward.py` is **strictly decoupled from execution**. It does NOT invoke the sandbox, run graphs, or pick seeds. It purely consumes structured evaluation results (`CandidateResult`) and group context, computing scalar rewards and advantage normalizations. This guarantees that reward calculation is fast, deterministic, and testable without sandbox overhead.

### 4.2 Data Structures & Config Dataclass

```python
from dataclasses import dataclass, field
from typing import List, Optional, Sequence
import numpy as np


@dataclass
class CandidateResult:
    """Evaluation result for one candidate on a group's graph set S."""
    status: str  # "ok", "ast_fail", "purity_fail", "timeout", "memory", "invalid_coloring", "exception"
    colors_per_graph: List[int] = field(default_factory=list)
    runtime_per_graph: List[float] = field(default_factory=list)
    probe_orderings: Optional[List[np.ndarray]] = None  # 2 probe vertex orderings (or None)
    code: Optional[str] = None


@dataclass
class RewardConfig:
    """Hyperparameters and coefficients for GRPO reward (Section 14.3)."""
    a: float = 0.0              # weight for r_tb (tie-breaking), default 0.0 (OFF)
    b: float = 0.1              # weight for r_time (runtime penalty), default 0.1
    d: float = 0.0              # weight for r_div (behavioral diversity), default 0.0 in A2/A3, 0.1 in A4
    time_factor: float = 2.0    # t_budget = time_factor * time_dsatur
    failure_reward: float = -1.0 # exact reward assigned to any failed candidate
    eps_std: float = 1e-8       # numerical stability for advantage normalization
    clip_sav_lo: float = -1.0   # lower bound for r_sav clipping
    clip_sav_hi: float = 1.0    # upper bound for r_sav clipping
```

### 4.3 `base_alg(card)` Helper
Per Decision D-3:
- Baseline is `base_alg(card)` computed on `teacher_val` (seeds 3000-3019).
- A lookup function maps `family_id` to its predetermined baseline algorithm (`"DSATUR"` or `"RLF"`).
- `c_base_per_graph`: The color counts of `base_alg(card)` on the graphs $S$ evaluated in this step.

### 4.4 Mathematical Formulas & Reward Components

For a group of $G$ candidates $\{h_1, \dots, h_G\}$ evaluated on the identical graph set $S$:

#### 1. Failure Handling
If candidate $h$ has `status != "ok"`:
$$r(h) = -1.0 \quad (\text{exact})$$
Failed candidates are **excluded** from pairwise diversity calculations.

#### 2. Color Savings Reward $r_{sav}$
For a successful candidate $h$:
$$r_{sav}(h) = \frac{1}{|S|} \sum_{g \in S} \text{clip}\left( \frac{c_{base}(g) - c_h(g)}{\max\left(1.0, \; c_{base}(g) - c_{ref}(g)\right)}, \; -1.0, \; 1.0 \right)$$
- If $c_{ref}$ is None, the fallback is $c_{base}(g) - 1.0$, which simplifies the denominator to $\max(1.0, 1.0) = 1.0$.
- Denominator protection prevents division by zero or negative scaling.
- If $c_h(g) = c_{base}(g)$ (copies baseline), $r_{sav}(h) = 0.0$.
- If $c_h(g) < c_{base}(g)$ (improves on baseline), $r_{sav}(h) > 0.0$.
- If $c_h(g) > c_{base}(g)$ (worse than baseline), $r_{sav}(h) < 0.0$.

#### 3. Runtime Penalty $r_{time}$
Let $t_h = \text{mean}(runtime\_per\_graph)$ and $t_{dsatur} = \text{mean}(t\_dsatur\_per\_graph)$.
Budget is defined as $t_{budget} = \text{time\_factor} \times t_{dsatur}$.
$$r_{time}(h) = \text{clip}\left( \frac{t_h}{t_{budget}} - 1.0, \; 0.0, \; 1.0 \right)$$
- If $t_h \le t_{budget}$, $r_{time}(h) = 0.0$ (no penalty within budget).
- If $t_h > t_{budget}$, penalty scales linearly up to $1.0$ at $t_h \ge 2 \times t_{budget}$.

#### 4. Tie-Breaking Reward $r_{tb}$
Optional term (default $a = 0.0$). If enabled, measures color class size concentration:
$$r_{tb}(h) = \frac{1}{|S|} \sum_{g \in S} \sum_{c} \left(\frac{|V_c|}{n}\right)^2 \in [0.0, 1.0]$$

#### 5. Pre-Reward $r_{pre}$
$$r_{pre}(h) = r_{sav}(h) + a \cdot r_{tb}(h) - b \cdot r_{time}(h)$$

#### 6. Behavioral Diversity Reward $r_{div}$
- Filter candidates in group to successful candidates: $V = \{i \mid status_i == \text{"ok"}\}$.
- Compute group median of $r_{pre}$ across the entire group: $M_{pre} = \text{median}(\{r_{pre}(i) \mid i \in \{1,\dots,G\}\})$.
- Diversity reward is applied **ONLY** to candidates strictly above median:
  $$\text{eligible}(i) \iff i \in V \text{ and } r_{pre}(i) > M_{pre}$$
- If candidate $i$ is not eligible or $|V \setminus \{i\}| = 0$, $r_{div}(i) = 0.0$.
- Otherwise:
  $$r_{div}(i) = \frac{1}{|V \setminus \{i\}|} \sum_{j \in V \setminus \{i\}} \bar{\tau}_{dist}(\text{probe}_i, \text{probe}_j)$$
  where $\bar{\tau}_{dist}$ is the average normalized Kendall-tau distance across the 2 probe graphs.

#### 7. Normalized Kendall-Tau Distance
For two permutations $\pi_1, \pi_2$ of $N_p$ probe vertices:
$$d_\tau(\pi_1, \pi_2) = \sum_{u < v} \mathbb{I}\left[(\pi_1(u) < \pi_1(v)) \neq (\pi_2(u) < \pi_2(v))\right]$$
$$\tau_{dist}(\pi_1, \pi_2) = \frac{d_\tau(\pi_1, \pi_2)}{\frac{1}{2} N_p (N_p - 1)} \in [0.0, 1.0]$$
- Identical orderings $\implies \tau_{dist} = 0.0$.
- Reversed orderings $\implies \tau_{dist} = 1.0$.

#### 8. Final Reward $r(h)$
For candidate $h$:
$$r(h) = \begin{cases} -1.0, & \text{if } status_h \neq \text{"ok"} \\ r_{pre}(h) + d \cdot r_{div}(h), & \text{if } status_h == \text{"ok"} \end{cases}$$

### 4.5 Mathematical Proof of Reward Bounds
Given hyperparameters $a \ge 0, b \ge 0, d \ge 0$:
1. **Lower Bound:**
   - For failed candidates: $r = -1.0$.
   - For valid candidates:
     $r_{sav} \ge -1.0$
     $a \cdot r_{tb} \ge 0.0$
     $-b \cdot r_{time} \ge -b$
     $d \cdot r_{div} \ge 0.0$
     Thus: $r \ge -1.0 - b$.
   - Global minimum: $\min(-1.0, -1.0 - b) = -1.0 - b$.
2. **Upper Bound:**
   - $r_{sav} \le 1.0$
   - $a \cdot r_{tb} \le a$
   - $-b \cdot r_{time} \le 0.0$
   - $d \cdot r_{div} \le d$
   - Global maximum: $1.0 + a + d$.

**Conclusion:**
For any candidate $h$:
$$r(h) \in [-1.0 - b, \; 1.0 + a + d]$$
Under default parameters ($a = 0.0, b = 0.1, d = 0.0$):
$$r(h) \in [-1.1, \; 1.0]$$
When diversity is active ($d = 0.1$):
$$r(h) \in [-1.1, \; 1.1]$$

### 4.6 Group Advantage Normalization
For group rewards $\mathbf{r} = [r_1, \dots, r_G]$:
1. Population mean: $\mu = \frac{1}{G} \sum_{i=1}^G r_i$.
2. Population standard deviation (`ddof=0`):
   $$\sigma = \sqrt{\frac{1}{G} \sum_{i=1}^G (r_i - \mu)^2}$$
3. Advantage calculation:
   $$A_i = \begin{cases} 0.0, & \text{if } \sigma \le \epsilon_{std} \\ \frac{r_i - \mu}{\sigma + \epsilon_{std}}, & \text{if } \sigma > \epsilon_{std} \end{cases}$$
- **Zero Variance Invariant:** If all candidates have identical rewards (e.g. all fail and get $-1.0$, or all match baseline and get $0.0$), $\sigma = 0$, and every advantage $A_i$ is set to **$0.0$ exactly** without NaN or Inf.
